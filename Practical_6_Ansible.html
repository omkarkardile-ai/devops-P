PRACTICAL 6

Introduction to Ansible — Step-by-step execution guide

Objective: Configure one Ansible Control Node and two Managed Nodes. Install Ansible, connect to the remote machines, install required packages, start Apache, copy a web page, and verify idempotency.

Important: Run the control-node commands inside Ubuntu (WSL or a Linux VM). The two managed nodes must be separate Ubuntu/Linux machines reachable over SSH. Replace every example IP address and username with your actual values.

1. Understand the setup

CONTROL NODE (Ubuntu / WSL)
        |
        | SSH
        +----------> MANAGED NODE 1 (Ubuntu)
        |
        +----------> MANAGED NODE 2 (Ubuntu)

Example values used in this guide (change them to yours):

Control node: Ubuntu
Managed node 1 IP: 192.168.1.101
Managed node 2 IP: 192.168.1.102
Remote username: ubuntu

The IP addresses above are examples only. Do not copy them unless they match your machines.

2. Prepare the two Managed Nodes

Perform these commands on both managed Ubuntu machines. Open a terminal on each machine.

sudo apt update
sudo apt install openssh-server python3 -y
sudo systemctl enable --now ssh
sudo systemctl status ssh

Find each managed node's IP address:

hostname -I

Write down the IP address of each node. Make sure the control node can reach both machines. You should also know the login username on each managed node.

3. Install Ansible on the Control Node

Open Ubuntu on your control node (for example, Ubuntu in WSL). Run:

sudo apt update
sudo apt install ansible -y
ansible --version

The last command should display the installed Ansible version.

4. Test SSH connection to both Managed Nodes

From the control node, test that you can log in to each remote machine. Replace the IP and username:

ssh ubuntu@192.168.1.101
# Enter the remote user's password if asked.
# Type exit to return to the control node.

ssh ubuntu@192.168.1.102
# Type exit to return to the control node.

For password-free SSH login (recommended), run on the control node:

ssh-keygen -t ed25519
# Press Enter to accept the default file and optional passphrase.

ssh-copy-id ubuntu@192.168.1.101
ssh-copy-id ubuntu@192.168.1.102
If ssh-copy-id is unavailable, copy the public key from ~/.ssh/id_ed25519.pub into the remote user's ~/.ssh/authorized_keys file. Do not share your private key.

5. Create the project folder and inventory file

mkdir -p ~/ansible-practical
cd ~/ansible-practical
nano inventory.ini

Paste this inventory. Replace the example IP addresses and username:

[webservers]
192.168.1.101 ansible_user=ubuntu
192.168.1.102 ansible_user=ubuntu

Save in nano: press Ctrl + O, Enter, then Ctrl + X.

Check the inventory:

cat inventory.ini

6. Test connectivity using Ansible ping

Run this command from the project folder on the control node:

ansible all -i inventory.ini -m ping

Expected result: both managed nodes should return "ping": "pong" and show SUCCESS.

If you get an SSH or permission error: check the IP, username, SSH service on the managed node, and SSH login. If you use password-based login, install sshpass on the control node and run ansible all -i inventory.ini -m ping -k.

7. Create the Ansible Playbook

Create the playbook file:

nano install-packages.yml

Paste the complete code below:

---
- name: Configure web servers
  hosts: webservers
  become: yes

  tasks:
    - name: Update apt cache
      apt:
        update_cache: yes

    - name: Install required packages
      apt:
        name:
          - apache2
          - curl
          - git
          - vim
        state: present

    - name: Ensure Apache is started and enabled
      service:
        name: apache2
        state: started
        enabled: yes

    - name: Copy custom web page
      copy:
        content: "<h1>Hello from Ansible</h1>"
        dest: /var/www/html/index.html
        owner: root
        group: root
        mode: '0644'

Save: Ctrl + O, Enter, Ctrl + X.

This playbook performs all four required tasks: updates apt cache, installs apache2/curl/git/vim, starts and enables Apache, and copies the custom index.html file.

8. Run the Playbook

Run from the folder containing both files:

ansible-playbook -i inventory.ini install-packages.yml

If Ansible asks for a sudo password on the remote machines, use:

ansible-playbook -i inventory.ini install-packages.yml -K

Enter the remote user's sudo password when prompted. The play recap should list both managed nodes. On the first run, some tasks should show changed.

9. Verify Apache in the Browser

Open a browser on a machine that can reach the managed nodes. Visit both addresses:

http://192.168.1.101
http://192.168.1.102

You should see the message: Hello from Ansible. Use your actual managed-node IP addresses.

You can also test from the control node:

curl http://192.168.1.101
curl http://192.168.1.102

10. Prove Idempotency (changed=0)

Run the exact same playbook again:

ansible-playbook -i inventory.ini install-packages.yml

Because the packages, service state, and file content are already correct, the second run should show changed=0 for each managed node (assuming no configuration has changed). This demonstrates Ansible idempotency.

11. Useful commands for the exam

# Show Ansible version
ansible --version

# Check inventory hosts
ansible all -i inventory.ini --list-hosts

# Ping both managed nodes
ansible all -i inventory.ini -m ping

# Run the playbook
ansible-playbook -i inventory.ini install-packages.yml

# Run with sudo password prompt
ansible-playbook -i inventory.ini install-packages.yml -K

# Check Apache service on both nodes
ansible webservers -i inventory.ini -m service -a "name=apache2 state=started"

# Check the web page from the control node
curl http://192.168.1.101
curl http://192.168.1.102
